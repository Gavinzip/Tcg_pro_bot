## 修改與排程語義

舊程式每輪完成後固定 sleep(interval)，所以 6 秒工作加 60 秒等待，下一輪在第 66 秒開始。
現在僅對 event-leaderboards 使用 monotonic 時計扣除本輪已花的時間（包括備份優先鎖的等待、子程序啟動／掃描與清理），等待 max(0, 60 − 本輪耗時)。
同一個協程 await 整輪工作完成後才進下一輪，不新增平行 timer 或 catch-up 任務。
若超過 60 秒，完成後讓出 event loop 並接續一輪；下一個間隔從新的實際起點算，不補開欠下的輪數。程序停機時不會重播錯過的排程。

| 本輪工作耗時 | 剩餘等待 | 下一輪開始 |
| --- | --- | --- |
| 6 秒 | 54 秒 | 上輪開始後 60 秒 |
| 12 秒 | 48 秒 | 上輪開始後 60 秒 |
| 60 秒 | 0 秒 | 完成後接續 |
| 85 秒 | 0 秒 | 上輪開始後 85 秒 |
| 605 秒 | 0 秒 | 完成後只接續一輪 |

使用 monotonic 時計，不受系統日期校正影響。這是排程目標，不是作業系統即時啟動保證。
每日備份仍依成功完成時間與原有間隔排程；失敗處理、取消／逾時清理、掃描優先鎖、4 RPS、64 confirmations、五分鐘回掃與計票不變。沒有新增 fallback。
